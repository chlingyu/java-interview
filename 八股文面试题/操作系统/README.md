# 操作系统

## 一、进程与线程

### 1. 进程和线程有什么区别？

**一句话总结**：**进程**是资源分配的基本单位（有独立的内存空间），**线程**是 CPU 调度的基本单位（共享进程的内存空间）。一个进程可以包含多个线程。

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 定义 | **资源分配**的基本单位 | **CPU 调度**的基本单位 |
| 内存空间 | **独立**的地址空间 | **共享**进程的地址空间 |
| 创建/切换开销 | **大** | **小** |
| 通信方式 | 管道、消息队列、共享内存等（IPC） | 直接读写共享变量（需要同步） |
| 崩溃影响 | 一个进程崩溃不影响其他进程 | 一个线程崩溃**整个进程**都会崩 |

**背诵口诀**：「**进程管资源，线程管执行，线程共享进程的内存**」

---

### 2. 进程间通信（IPC）有哪些方式？

**一句话总结**：常见的 IPC 方式有 **管道、消息队列、共享内存、信号量、Socket** 等。

| 方式 | 特点 | 使用场景 |
|------|------|---------|
| **管道（Pipe）** | 单向通信，父子进程间使用 | 简单的命令行管道（如 `ls | grep`） |
| **消息队列** | 存在内核中的消息链表，支持按类型读取 | 进程间传递结构化数据 |
| **共享内存** | 多个进程共享同一块内存，**速度最快** | 大量数据传递 |
| **信号量（Semaphore）** | 用于进程同步（控制访问共享资源的数量） | 配合共享内存使用 |
| **Socket** | 支持不同机器间的通信 | 网络通信 |

---

### 3. 进程有哪几种状态？

**一句话总结**：进程有 **5 种基本状态**：创建、就绪、运行、阻塞、终止。

```
创建 → 就绪 ←→ 运行 → 终止
              ↓   ↑
             阻塞 ─┘
```

| 状态 | 含义 |
|------|------|
| **创建** | 进程正在被创建 |
| **就绪** | 等待 CPU 分配时间片 |
| **运行** | 正在占用 CPU 执行 |
| **阻塞** | 等待某个事件（如 IO 完成），CPU 切给别人 |
| **终止** | 进程执行完毕或被杀死 |

## 二、调度与同步

### 4. 常见的进程调度算法有哪些？

**一句话总结**：面试常考 **FCFS（先来先服务）、SJF（短作业优先）、RR（时间片轮转）、优先级调度**。

| 算法 | 原理 | 优缺点 |
|------|------|--------|
| **FCFS** | 按到达顺序执行 | 简单，但短任务等太久 |
| **SJF** | 执行时间最短的先执行 | 平均等待时间最短，但可能饿死长任务 |
| **RR（时间片轮转）** | 每个进程分配一个时间片，轮流执行 | 公平，响应快（适合交互系统） |
| **优先级调度** | 优先级高的先执行 | 灵活，但低优先级可能饿死 |

---

### 5. 什么是死锁？产生条件和解决方法？

**一句话总结**：和 Java 并发中的死锁一样 —— 多个进程互相持有对方需要的资源，导致都无法继续执行。

**4 个必要条件**（与 Java 并发第 14 题一致，详见该题）：
- 互斥、持有并等待、不可抢占、循环等待

**解决方法**：
- **预防**：破坏四个条件之一（如按固定顺序申请资源 → 打破循环等待）
- **避免**：银行家算法（在分配资源前判断是否安全）
- **检测 + 恢复**：允许死锁发生，检测到后杀掉某个进程

## 三、内存管理

### 6. 什么是虚拟内存？

**一句话总结**：虚拟内存让每个进程以为自己拥有**完整的、连续的内存空间**，实际上是通过**页表**映射到物理内存的不同位置。不常用的数据可以暂时放到磁盘上。

**虚拟内存的好处**：
- **隔离**：每个进程有独立的地址空间，互不干扰
- **扩展**：程序可以使用比物理内存更大的地址空间
- **保护**：防止进程访问其他进程的内存

**⚠️ 面试挖坑提醒**：「什么是页面置换算法？」—— 当物理内存满了，需要把某些页换到磁盘。常见算法：**LRU**（最近最少使用，详见 Java 集合第 10 题 LinkedHashMap）、FIFO（先进先出）、OPT（最优但不可实现）。

---

### 7. 进程的内存布局是怎样的？

**一句话总结**：进程的内存从低到高依次是：代码段 → 数据段 → 堆（向上增长）→ 栈（向下增长）。

```
高地址 ┌────────────┐
       │    栈       │ ← 局部变量、函数调用（向下增长）
       │    ↓       │
       │            │
       │    ↑       │
       │    堆       │ ← new/malloc 分配的对象（向上增长）
       ├────────────┤
       │  数据段     │ ← 全局变量、静态变量
       ├────────────┤
       │  代码段     │ ← 程序的机器指令（只读）
低地址 └────────────┘
```

---

### 8. 用户态和内核态有什么区别？

**一句话总结**：**用户态**是程序正常运行的状态，权限低；**内核态**是操作系统内核运行的状态，权限高（可以访问硬件）。程序通过**系统调用**从用户态切换到内核态。

| 对比项 | 用户态 | 内核态 |
|--------|--------|--------|
| 权限 | **低**（不能直接访问硬件） | **高**（可以访问所有资源） |
| 运行的代码 | 应用程序代码 | 操作系统内核代码 |
| 切换方式 | 系统调用、中断、异常 | — |
| 举例 | 普通的 Java 代码执行 | 文件读写、网络操作、创建线程 |

**⚠️ 面试挖坑提醒**：「为什么要区分用户态和内核态？」—— 为了**安全**。如果所有程序都能直接操作硬件，一个有 bug 的程序可能把整个系统搞崩。通过划分权限，只有内核才能操作硬件，应用程序必须通过系统调用请求内核帮忙。

### 9. IO 模型有哪些？BIO、NIO、AIO 有什么区别？

**一句话总结**：IO 模型描述的是应用程序**等待数据**和**读取数据**时的行为方式。常见有 4 种：**同步阻塞（BIO）**、**同步非阻塞**、**IO 多路复用（NIO）**、**异步 IO（AIO）**。Java 后端面试重点考的是 BIO、NIO 和多路复用。

| IO 模型 | 等数据时 | 拷贝数据时 | 通俗理解 |
|---------|---------|-----------|---------|
| **BIO（同步阻塞）** | 阻塞等待 | 阻塞等待 | 食堂打饭：排队等着，打完饭才能走。**一个线程只能服务一个连接** |
| **同步非阻塞 IO**（注意：不是 Java NIO 包） | 轮询检查 | 阻塞等待 | 不排队，时不时跑去看饭好没好。**轮询浪费 CPU，实际很少单独使用** |
| **IO 多路复用** | **一个线程监控多个连接** | 阻塞等待 | 食堂装了叫号屏（select/epoll），屏幕亮了再去拿。**主流方案** |
| **AIO（异步 IO）** | 不等待 | 不等待 | 外卖送到家门口再通知你。数据准备好后**内核主动通知** |

**IO 多路复用的 3 种实现**（面试重点）：

| 实现 | 特点 |
|------|------|
| **select** | 最早的实现，在 Linux 常见默认实现中有 1024 个文件描述符上限，每次都要遍历所有连接 |
| **poll** | 去掉了 1024 限制，但仍需要遍历 |
| **epoll** | Linux 高性能方案。**事件驱动**，不用遍历，只返回有事件的连接。Redis、Nginx、Netty 都用 epoll |

**Java 中的 IO 模型对应**：

| Java API | 对应 IO 模型 | 使用场景 |
|----------|-------------|---------|
| `java.io`（InputStream/OutputStream） | **BIO** | 连接数少的简单场景 |
| `java.nio`（Channel/Buffer/Selector） | **IO 多路复用** | 高并发网络通信（Netty 底层就是 NIO） |
| `java.nio2`（AsynchronousChannel） | **AIO** | 理论上更好，但 Linux 的 AIO 实现不成熟，实际用得少 |

**背诵口诀**：「**BIO 一线程一连接，Java NIO + Selector 一线程多连接靠多路复用，AIO 内核通知全自动**」

> ⁉️ **概念区分**：操作系统层面的“同步非阻塞 IO”是指应用程序轮询检查数据是否就绪，实际很少单独使用。Java 面试里常说的「NIO」更多是指 `java.nio` + `Selector` 的 **IO 多路复用**方案，不等于单纯的轮询検查。面试时说“Java NIO 基于多路复用”最准确。

> **面试话术**：IO 模型主要有四种。BIO 是同步阻塞，一个线程只能处理一个连接，并发能力差。NIO 配合 IO 多路复用是主流方案，像 select 或 epoll，一个线程可以同时监控成千上万个连接，有数据就绪了再去处理。Java 的 NIO 包提供了 Channel、Buffer、Selector 来实现多路复用，Netty 和 Redis 底层都是基于 epoll。AIO 是异步 IO，理论上最好，但 Linux 的实现不太成熟，实际项目中用得不多。

**⚠️ 面试挖坑提醒**：「Java NIO 中的 NIO 是 Non-blocking IO 还是 New IO？」—— 严格说是 **New IO**（新 IO），但实际实现的是 **IO 多路复用模型**（基于 Selector），不是纯粹的非阻塞 IO。面试时说"Java NIO 基于多路复用"最准确。

**关联知识点**：第 8 题用户态/内核态的切换就发生在 IO 操作中——数据从网卡到内核缓冲区（内核态），再从内核缓冲区拷贝到用户缓冲区（用户态），这就是为什么 IO 操作涉及系统调用和态切换。JVM 直接内存（详见 JVM 第 16 题）通过减少这次拷贝来提升 IO 性能。
